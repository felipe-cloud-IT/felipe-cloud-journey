## Método para cada ficha del portafolio

1. Problema y contexto ficticio o anonimizado.
2. Competencia técnica demostrada.
3. Herramientas y arquitectura.
4. Implementación reproducible.
5. Pruebas, resultados y limitaciones.
6. Evidencia adjunta y fecha de verificación.
7. Lecciones aprendidas y próximos pasos.

## Reglas

- GitHub público: código autorizado, documentación técnica y evidencias sin secretos ni datos reales de clientes o empleadores.
- Google Drive: archivos de trabajo, fuentes, respaldos y documentos personales o internos.
- La existencia de código o de un README **no acredita por sí sola** un proyecto como validado.
- Prioridad: revisar Fénix Estadístico y Fénix Infra Lab antes de iniciar proyectos nuevos.
